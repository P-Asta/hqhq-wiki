# Completeness Critique — engine design docs

Reviewer: completeness critic · Date: 2026-08-31
Scope: `wikitext-spec.md`, `reuse-audit.md`, `db-schema.md`, `seed-content-plan.md` (all read in full, cross-checked against each other and against every wikitext construct in the seed fixtures).

Verdict: the seed fixtures' syntax is fully covered by the spec (checked construct-by-construct — headings, apostrophes, links/red links/piped, external links, wikitables, raw-HTML infobox subset incl. attrs, `{{…}}`/`{{{…|…}}}`, `#if`/`#ifeq`/`#switch` incl. fall-through and `#default`, nested transclusion in args and in attribute values, `<ref>`/named/reuse/`<references/>`, categories incl. template-injected, `[[File:|260px|alt]]`, entities, `<code>`, `:`-indent, CJK text). The gaps found were at the *seams between the docs*, plus one real rendering edge the fixtures trigger. Small gaps were fixed in-place via `## Addendum (critic)` sections; larger ones are open decisions below.

---

## Fixed (doc amended, normative)

- **F1 — Blank lines inside raw HTML tables produce garbage paragraphs** (seed infoboxes with omitted params → consecutive blank lines between `<tr>`s; §3.2 as written would emit `<p><br /></p>` inside `<table>`). Fixed in **wikitext-spec.md Addendum A1** (new divergence D-14: blank lines emit nothing while a p-rejecting raw element is open); regression fixture = KO Titan infobox. Cross-noted in **seed-content-plan.md Addendum**.
- **F2 — Contradictory redirect metadata shapes** inside the spec (§12.4 `{ target, fragment? }` vs §14.10 `{ target: Title }`). Fixed in **wikitext-spec.md Addendum A2**: fragment lives on `Title.fragment`; C-70 assertion updated accordingly.
- **F3 — Parser-emitted UI strings were hardcoded English** ("Contents" TOC title, "(page does not exist)", "Redirect to:", cite/loop errors) — an i18n hole for KO pages. Fixed in **wikitext-spec.md Addendum A3**: `WikiConfig.messages` supplied per rendering locale (safe because render cache is keyed `(page_id, locale)`). Also confirmed there: Korean heading anchors/TOC ids already work via §2.4 html5 fragment mode — no change needed.
- **F4 — Cache invalidation contract underspecified for transitive/missing templates.** `template_links` fed by source-level extraction would miss template-in-template deps and red-linked templates. Fixed in **wikitext-spec.md Addendum A4** (`templatesUsed` must include transitive + nonexistent targets; `linksTo` includes red links) and **db-schema.md Addendum A4** (link tables and `search_docs.body` MUST derive from `ParseResult.meta`, not regex; reuse the save-time parse to warm the cache).
- **F5 — Admin model contradiction**: db-schema had `users.role` enum; reuse-audit requires keeping `auth/server.ts` with a single `hasActiveGrant(uid)` swap plus grant semantics (history, no self-revoke, banned-never-admin). Fixed in **db-schema.md Addendum A1**: `admin_grants` table added, `users.role` dropped, `isAdmin` stays request-computed (Firestore bootstrap roles OR active grant). Cross-noted in **reuse-audit.md Addendum**.
- **F6 — Redirect fragments had no storage** (`#REDIRECT [[Moons#Titan]]` legal per spec §12.1; `pages` had only ns+slug). Fixed in **db-schema.md Addendum A2**: `redirect_fragment` column; `parseRedirect` must reuse the engine's §12.1 recognizer.
- **F7 — Red/blue link staleness in the render cache**: no invalidation existed for page create/delete/undelete/rename (cached HTML embeds link colors). Fixed in **db-schema.md Addendum A3**: delete dependents' cache rows via `page_links`/`template_links` target indexes inside the same transaction.
- **F8 — Volatile output cached forever**: spec flags `meta.volatile` for `CURRENT*`/`#ifexist`, but the cache design ignored it. Fixed in **db-schema.md Addendum A5**: volatile results skip the `parsed_cache` upsert.
- **F9 — Page deletion orphans `search_docs`** (no FK, triggers never fire → ghost FTS results); no delete procedure existed at all. Fixed in **db-schema.md Addendum A6**: explicit delete ordering (search_docs → pages cascade → A3 invalidation → audit row).
- **F10 — Namespace systems inconsistent across docs**: spec has 16 numeric MW namespaces (`Help:` etc. as *known*), db-schema has a 5-string enum; `page_links.to_namespace` could not even store a `[[Help:Style]]` target. Fixed in **db-schema.md Addendum A7**: canonical mapping `0↔main, 4↔project, 6↔file, 10↔template, 14↔category`; all other namespaces are storage-less — uncreatable, always-red, excluded from `page_links`. (Whether to instead extend the enum stays open, O2.)
- **F11 — Template locale fallback had no stance**: `PageStore.getSource` has no locale param, yet templates are pages with per-locale revisions. Fixed in **db-schema.md Addendum A8** (+ seed-plan addendum): transclusion always resolves to the template's **EN head revision**; non-EN template revisions are ignored by the renderer; #12's invalidation unchanged. Matches the seed plan's "templates are locale-neutral" and its KO fixture (localized values via params).
- **F12 — Seed plan targeted the legacy file store** (`page-moons-titan` ids, `template-` slug prefixes, store `category` field, `translations/ko`). Fixed in **seed-content-plan.md Addendum**: explicit mapping to `(namespace, slug)` + `revisions.locale`; `template-` prefix dropped in favor of the namespace column.
- **F13 — Seed red-link inventory incomplete**: Titan also red-links `[[Eyeless Dog]]` and `[[Extension ladder]]` (absent from the 28-page inventory) — the §3.1 note and §5 coverage matrix understated the fixture's red-link assertions. Corrected in **seed-content-plan.md Addendum**.
- **F14 — Missing-file rendering mismatch**: seed plan said "placeholder box", spec §5.9 says red file link. Fixed in **seed-content-plan.md Addendum**: the red link *is* the placeholder; no extra construct.
- **F15 — `articlePath` vs locale routing**: spec examples use `/wiki/$1` but the app routes under `/{locale}/…`. Clarified in **wikitext-spec.md Addendum A5**: config instantiated per locale; what fills `$1` depends on O1.
- **F16 — Edit-API auth path confirmed and documented as fitting**: recorded in **reuse-audit.md Addendum** — mutation routes reuse `authenticateRequest`/`authenticateAdminRequest` Bearer-per-request verification (stateless, no cookie, works with logged-out SSR), with the one new requirement that authenticated writes upsert the SQLite users mirror (db-schema §D pattern 15) so `author_uid`/`actor_uid` FKs resolve.

## Verified OK (explicitly checked, no change needed)

- **`<ref>` definitions need no DB home**: refs are render-scoped (numbered at spec stage 6); the rendered footnote list is part of the cached HTML in `parsed_cache`. Correct as designed.
- **FTS syncs on rollback**: rollback routes through `saveEdit` → `upsertSearchDoc` → the `search_docs` triggers; link graph, redirect/category refresh (EN branch), cache drop, and conflict detection all come along. Correct as designed.
- **Template-edit cache invalidation** (#12) is sound *given F4* (parser-fed, transitive `template_links`).
- **Korean FTS**: `unicode61 remove_diacritics 2` + prefix-star queries + documented future trigram option — reasonable and internally consistent (db-schema §B).
- **Korean anchors/TOC ids**: §2.4 html5 fragment mode handles Hangul; percent-encoding only in `href` fragments.
- **Seed fixture syntax vs spec**: every construct in the fixtures is specified, including the stress cases (nested `{{Verify}}` in param values, template calls inside HTML attribute values, `{{#switch}}` fall-through `S++|S+|S=…`, `&sup2;`-style entities, category injection from templates, `[verify]` not being parsed as an external link).

## Open decisions for the lead engineer

- **O1 — Title↔slug resolution rule (blocking; biggest gap).** Wikitext links carry MW titles (`[[Gold bar]]`, `[[The Company (71-Gordion)|…]]`); DB identity is `(namespace, slug)` with hand-assigned kebab slugs; `page_links.to_slug` and red/blue resolution require a *deterministic* title→slug function or an alias/lookup table — none is documented in any doc. Recommendation: `slug = slugify(normalized title)` (lowercase, spaces→`-`, strip non-URL-safe) + redirect rows for vanity slugs. Known collisions under that rule (seed addendum): `company-selling` and `gordion` need renames or redirects; bare moon links (`[[Titan]]` vs title `8-Titan`) then work only because assigned slugs match the bare names — decide whether display titles are freely decoupled from slugs (they are, via `page_locales.title`). This decision also fixes what `$1` means in `articlePath` (spec Addendum A5) and how category names map to `category_links.category_slug`.
- **O2 — Namespace enum coverage.** db-schema Addendum A7 makes non-mapped namespaces (Help, User, Talk…) uncreatable and unrecorded. Confirm that is acceptable (spec §5.8 still *parses* them; `{{TALKPAGENAME}}` computes a name for a page that can never exist), or extend `NAMESPACES` now — extending later is one migration, but `page_links` rows written before the extension will be missing for those targets.
- **O3 — Navigation-category metadata has no home.** The old store's `categories.json` (per-category EN/KO labels, sortOrder, description — and the seed plan's proposed `strategies` addition) has no db-schema equivalent; `category_links` holds membership only. Options: (a) Category-namespace pages carry the metadata; (b) a small `categories` table (slug, per-locale labels, sort_order, description). The seed plan's "store category field is canonical for navigation" is currently unimplementable — pick one and define the `categories.json` migration.
- **O4 — First-created-in-non-EN pages.** Slugs are "EN-derived", but nothing forbids creating a page KO-first (no EN revision exists): where does the slug come from, must an EN `page_locales` row exist, and the outdated-translation query counts a missing basis as outdated — confirm the intended UX for EN-less pages (`getPageView` reads them fine already).
- **O5 — `banned` dual source of truth.** Firestore `profile.banned` (auth pipeline, authoritative) vs SQLite `users.banned`. Recommended in reuse-audit Addendum: keep Firestore authoritative; the SQLite column is a moderation-view mirror written in the same admin action — or drop the column. Confirm.
- **O6 — Media serving + filename normalization.** No route is defined for serving `wiki-data/uploads/` binaries (`PageStore.getFile().src` format unspecified), and `files.filename` normalization vs spec §5.7 title rules (first-letter case-insensitivity, `_`↔space; seed uses lowercase `moon-titan.png`) is undefined — the unique index needs a stated canonical form.
- **O7 — Search locale fallback.** `search()` filters `d.locale = :locale`, so a KO reader's search misses EN-only pages even though page *viewing* falls back to EN. Decide: union EN results (deduped, flagged) or keep strict per-locale search.
- **O8 — Route map document does not exist.** The reuse-audit prescribes conventions (guards, error bodies) and db-schema implies endpoints, but no doc enumerates the new routes (view/edit/history/diff/rollback/search/upload/admin/languages) with auth level and error shape — including the audit's own warning that `/api/auth/me`'s error-body shape must stay as-is if `auth/client.ts` is kept verbatim while everything else unifies on `api-response.ts`. Write it before implementation.
- **O9 — Seed slug collisions** (`selling-at-the-company` → `company-selling`, `the-company-71-gordion` → `gordion`): once O1 is decided, either rename the two slugs or seed redirect pages; also decide whether number-prefixed titles (`8-Titan`) each get a bare-name redirect (`Titan` → `8-Titan`) for MW-style linking, or whether bare-name slugs make that moot.
